# 시험

에이전트가 실제 사례에서 원하는 판정을 내는지 본다. 정답과 사례 대응은 **이 파일에만** 둔다. 에이전트에게는 이 파일을 주지 않는다.

## 돌리는 법

- 플러그인이 설치돼 있지 않으면 `agents/<이름>.md`의 본문을 general-purpose 서브에이전트 프롬프트로 넘기고, 아래 입력 파일의 절대 경로를 덧붙인다. 다른 파일은 열지 말라고 적는다.
- cold-reader 입력: 독자 요약서, fixture, (있으면) 그림
- rubric-reviewer 입력: `skills/write-explainer/references/review-rubric.md`, `claims-evidence.md`, fixture

## 기본 시험 (cold-reader, 일관성 확인용) — 비공개

사내 문서의 두 문단(비유로 설명한 문단, 잡음이 평균돼 줄어든다는 문단)을 고치기 전 판과 고친 판으로 나눠 4개 사례를 만들었다. 회사 문서라서 공개 저장소에는 넣지 않고 로컬 `evals/private/`에만 둔다(`.gitignore`).

- 정답: 고치기 전 판 2개는 사용자가 실제로 막혔다고 확인한 문단이다. 막힘 1건 이상이 정답이다.
- 합격선: 고치기 전 판 2개를 각 3회, 6회 모두 막힘으로 잡는다.
- 2026-11-11 결과: 합격(6/6). 고친 판 2개도 매번 실제 결함을 지적해 잠정 정답(막힘 없음)과 달랐다.
- 3회 일치는 판정이 흔들리지 않는지를 볼 뿐, 효과를 입증하지 않는다.

## 보류 시험 (프롬프트를 쓰는 동안 열지 않은 사례, 각 1회)

블로그 [XsQuare01.github.io](https://github.com/XsQuare01/XsQuare01.github.io)의 실제 사례.

| fixture | 출처 | 에이전트 | 정답 |
| --- | --- | --- | --- |
| h1 | 「점과 벡터」 현재본, 처음 ~ 「원점만 옮기면 무엇이 바뀌는가」 | cold-reader (`brief_blog.md`) | 막힘 없음이거나 경미한 것뿐. 판단 질문에 "원점만 옮기면 변위 성분은 그대로((3,4)), 축을 돌리면 달라질 수 있다"는 취지로 본문을 인용해 답한다 |
| h2 | 「평면 2관절 팔」 커밋 `263228c` 본문 | rubric-reviewer | 관절 제한·충돌을 제외한다는 적용 전제가 없어 '자세 0·1·2개' 같은 결론을 실제 로봇에 일반화할 수 있다는 지적(L7, 🟡 이상) |
| h3 | 「최대 부분배열」 커밋 `3183f4c` 27~154행 | rubric-reviewer | 코드는 반복 $j$에서 $P_j-m_{j-1}$을 읽는데 본문은 "두 코드가 매 자리에서 같은 값 $P_j-m_j=k_j$를 얻는다"고 설명한다는 지적(L7 또는 L4, 🟡 이상) |
| h4 | 「집합의 크기」 현재본, 「유한 집합」과 「중간 정리」 | rubric-reviewer | $B=\{0,1,\ldots,n\}$의 크기를 $n$으로 적었고 $n+1$이어야 한다는 지적(L7, 🔴 또는 🟡) |

- 작성자는 h2~h4의 결함을 블로그 리뷰 기록과 설계 검토로 미리 알고 있었다. 다만 에이전트 프롬프트를 쓸 때 이 fixture를 열지 않았고, 프롬프트에 사례별 힌트를 넣지 않았다.
- 보류 시험이 틀려도 v0에서는 프롬프트를 고치지 않고 기록만 한다. 고치면 그 사례는 더는 보류 시험이 아니라고 여기 적는다.
