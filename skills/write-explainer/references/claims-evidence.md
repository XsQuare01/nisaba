# 주장 근거 표와 근거 상태

스펙에는 주장마다 한 행을 둔다. 칸은 `ID · 원문 주장(위치) · 종류 · 논리식 또는 측정 조건 · 필요한 근거 · 가정·적용 범위 · 근거 상태 · 닫은 위치`다.
닫을 위치는 쓰기 전에 정한다. 정할 자리가 구조에 없으면 주장을 약하게 고치거나 그 논증을 담을 절을 만든다. 주장을 약하게 고치는 것도 의무를 닫는 방법이다.

## 주장 종류별 필요한 근거

| 주장 종류 | 필요한 근거 |
| --- | --- |
| 수학 주장 | 먼저 논리식으로 옮기고, 그 식이 요구하는 방향만 증명한다. 아래 「수학 주장」 절. |
| 수량 주장 (숫자든 기호든) | 근거 상태 하나, 단위, 반올림. 숫자 리터럴만이 아니라 "$B=\{0,\dots,n\}$의 크기는 $n+1$"처럼 기호로 쓴 크기도 포함한다. 기호 수량은 스크립트가 못 잡으니 rubric-reviewer가 이 표로 본다. |
| 공학 모델 주장 ("평균하면 줄어든다", "오차는 몇 mm") | 모델 가정(잡음이 서로 독립인가, 치우침이 있는가, 분포), 적용 범위, 불확실성, 경계·퇴화 사례. 아래 「공학 모델 주장」 절. |
| 설계 선택 ("A를 택했다") | 검토한 대안, 고른 기준, 버린 이유. 실제 결정 이유가 기록에 없으면 '확인 못 함'으로 쓴다. 작성자가 트레이드오프를 분석해 보이는 것은 되지만, 결정 이유처럼 쓰지 않고 분석이라고 밝힌다. |
| 효과 주장 ("빨라졌다", "정확해졌다") | 측정 조건, 방법, 전후 수치. 기대한 효과, 확인한 효과, 남은 문제를 나눈다. |
| 원인 주장 ("~때문이었다") | 재현 방법이나 디버깅 근거. 현상에 대한 잠정 설명은 가설로 쓰고 확인 방법을 붙인다. |
| 사용자 영향 주장 | 사용자가 화면이나 로봇 동작에서 보는 결과와 연결한다. |

## 근거 상태 (주장과 수량 공통)

| 상태 | 뜻 | 본문에서 | numbers.json `kind` |
| --- | --- | --- | --- |
| 측정 | 데이터·로그·실험에서 잰 값. 출처 경로와 조건을 적는다. | 조건을 함께 쓴다 | `측정` (`source` 필수, 데이터에서 다시 읽으면 `cmd`) |
| 계산 | 식과 입력이 있어 다시 계산할 수 있다. | 식이나 계산 방법을 보인다 | `계산` (`expr`나 `cmd` 필수) |
| 가정값 | 설명하려고 정한 값 | "가정한다", "예로 든다"라고 밝힌다 | `가정값` |
| 코드 사실 | 코드에서 확인한 동작·상수. 파일:줄과 커밋을 적는다. | 사내 참고나 출처 줄에 둔다 | `코드 사실` (`source` 필수) |
| 가설 | 현상의 원인에 대한 잠정 설명. 확인 방법을 붙인다. 수치나 다른 사람의 결정 이유에는 쓰지 않는다. | "가설"이라고 밝힌다 | (수량이 아니므로 표에만) |
| 확인 못 함 | 찾지 못한 수치나 결정 이유. 누가 또는 무엇이 확인해 줄 수 있는지 적는다. | 그렇다고 쓰거나 그 주장을 뺀다 | (등록하지 않는다) |

## 수학 주장

1. 원문 주장을 논리식으로 옮긴다.
2. 그 식이 요구하는 방향만 증명한다.
   - "A인 경우에만 B다"는 B ⇒ A 한 방향이다.[^only-if] 양방향은 필요충분("A이면, 그리고 그때만 B")일 때만 요구한다.
   - 예: 4의 배수이려면 짝수여야 한다(4의 배수 ⇒ 짝수). 짝수라고 다 4의 배수는 아니다.
   - 쓴 사람이 실제로 필요충분을 뜻했다면 문장을 "…이면, 그리고 그때만"으로 고치고 양방향을 닫는다.
3. 강한 한정사가 만드는 의무는 아래 표로 닫는다.

| 주장 형태 | 생기는 의무 | 닫는 방법 |
| --- | --- | --- |
| 모든 …에 대해 성립한다 | 완전성 | 임의 원소를 잡아 논증하거나 구조적 귀납으로 전 범위를 덮는다 |
| …만이 / …인 경우에만 | 필요조건 한 방향(B ⇒ A) | B를 가정해 A를 유도한다. 필요충분이면 반대 방향도 따로 닫는다 |
| 유일하다 | 존재성과 유일성 | 존재를 따로 보인 뒤, 서로 다른 둘을 가정해 같음을 유도한다 |
| 존재한다 / 항상 찾는다 | 존재성. 알고리즘을 두고 말하면 종료성과 완전성도 함께 | 구성해 보이거나 비존재 가정에서 모순을 얻는다 |
| 정확히 한 번 …한다 | 존재성과 중복 배제 | 최소 한 번과 두 번 이상 불가를 각각 닫는다 |
| 최적이다 | 최적성 | 임의 해와 비교하거나 교환 논증으로 손실 없음을 보인다 |
| 어떤 …도 …할 수 없다 / 하한이 …이다 | 불가능성 또는 하한 | 임의의 대상을 가정해 모순을 얻거나, 정보량·경우 수·환산으로 하한을 세운다 |
| 종료한다 | 종료성 | 0 이상인 정수 척도가 매 단계 감소함을 보인다 |

표에 없는 형태는 가장 가까운 행의 의무를 적고 그렇게 고른 이유를 남긴다.
함께 확인할 것: 가정·적용 영역·기호 정의를 증명 앞에 모았는가, 경우 구분이 서로 겹치지 않고 전체를 덮는가, 귀납의 base와 step을 각각 닫았는가, 경계·빈 입력·최소 크기 같은 퇴화 사례를 다루거나 다루지 않아도 되는 이유를 적었는가, 직관을 증명 자리에 두지 않았는가.

## 공학 모델 주장

- 어떤 잡음, 어떤 평균, 어떤 조건인지 밝힌다.
- 서로 독립이고 분산이 같은 오차를 산술평균하면 표준편차가 σ/√n으로 준다. 상관된 오차나 모든 측정에 같은 방향으로 들어가는 치우침(예: 틀린 마운트 오프셋)에는 이 계산을 쓰지 않는다. 치우침은 측정을 늘려도 줄지 않는다.
- 단순 평균의 성질을 추정 결과 전체(예: 캘리브레이션 정확도)의 성질로 옮겨 말하지 않는다. 측정점 배치, 추정 모델, 치우침의 영향을 따로 본다.
- 모의 계산으로 보이면 모의 조건(잡음 크기·분포·배치)과 '실측이 아님'을 본문이나 캡션에 쓴다.
- 경계·퇴화 사례(점이 한 직선·한 평면 위, 최소 개수)를 다루거나 다루지 않는 이유를 적는다.

[^only-if]: 블로그 저장소 [XsQuare01.github.io](https://github.com/XsQuare01/XsQuare01.github.io)의 `docs/writing-rules.md` 「강한 주장과 증명 의무」 표에서 옮겼다. 그 표의 '…인 경우에만' 행은 닫는 방법으로 두 방향 증명을 먼저 들어 필요충분과 섞일 수 있으므로 여기서는 한 방향으로 고쳤다(2026-11-11). 공학 모델 주장 절의 평균 규칙은 JCGM 100 (GUM) §4.2를 따른다.
