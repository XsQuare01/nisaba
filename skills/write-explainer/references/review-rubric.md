# 검토 루브릭 (L1–L7, R, P)

rubric-reviewer는 L1–L7과 P를, cold-reader는 R을 맡는다. 글은 고치지 않는다.

## 범주

- **L1 문체:** 줄표(—) 남발, 경구식 마무리, 수사적 비유("두 얼굴", "형제처럼"), 대칭 문장 반복, 과한 굵게. `korean-style.md`의 체크리스트를 함께 적용한다. 대응표가 있는 설명용 비유, 자문자답, 단계 설명은 지적하지 않는다(장르 예외). 강박 금지.
- **L2 설명 흐름:** 논리 도약, 빠진 전제, 정의 전에 쓰인 용어, 끊어야 할 긴 문장, 문장 사이 연결(같은 대상, 앞 결론 → 다음 전제, 조건 위치).
- **L3 용어·어체 일관성:** 같은 개념을 다른 말로 섞어 쓰는지, 시리즈 용어 사전과 맞는지, 어체 통일.
- **L4 표현 정렬:** 본문, 수식, 코드, 계산 예시, 그림(레이블·수치·캡션)이 같은 전제, 같은 순서, 같은 값, 같은 결론을 말하는지.
- **L5 제목:** 제목과 소제목이 실제 내용을 대표하는지.
- **L6 출처 충실성:** 코드·문서·논문·데이터와 대조한다. 판정은 아래 넷 중 하나를 `message` 맨 앞에 적는다.
  - `verified` 🟢 — 출처를 실제로 열어 대조했고 맞다.
  - `source unavailable` 🟡 — 출처를 열지 못했다. 검증 미완료로 남는다. `verified`로 적지 않는다.
  - `mismatch(국소)` 🟡 — 표현 차이나 부수적 누락.
  - `mismatch(핵심)` 🔴 — 동작, 수치, 인과를 바꾸는 불일치.
- **L7 정확성·근거:** `claims-evidence.md`가 기준이다.
  - 주장 근거 표의 행마다 닫힘·미닫힘을 적는다. 수학 주장은 논리식이 요구하는 방향만 요구한다.
  - **출력값 검산과 의미 대조를 나눠 본다.** 최종 값이 맞아도 코드·수식이 매 단계 계산하는 값을 본문이 다르게 설명하면 지적한다.
  - **적용 범위를 따로 본다.** 식이 맞아도 현실에 적용할 수 있는 전제(관절 제한, 충돌, 잡음 모델, 측정 조건)가 빠졌으면 지적한다.
  - 기호로 쓴 수량(집합의 크기, 인덱스 범위)을 직접 센다.
  - check_numbers의 미등록 숫자 중 수량 주장인 것을 골라 근거 상태를 묻는다. '출처만' 항목은 출처를 열 수 있으면 열어 본다.
  - 공학 모델 주장에 가정·적용 범위·불확실성·경계 사례가 있는지 본다.
  - 모르는 수치나 결정 이유가 가설로 채워졌으면 지적한다.
- **R 독자 (cold-reader):** 막힘(미정의 용어·기호, 단계 건너뜀, 비유 대응 불명, 답 없는 질문, 그림·본문 어긋남)과 오해(판단 질문의 답이 기대 답과 다름).
- **P 게시 화면 (게시 뒤):** 수식 렌더, 긴 식이 화면 폭에서 한 번에 읽히는지, 그림이 열리는지, 캡션이 맞는 그림 아래 있는지, 그림 글자가 게시 폭에서 읽히는지, 이해에 꼭 필요한 설명이 접힌 토글에 숨지 않았는지.

## 보고 형식

지적마다:

```
### <severity> [<rule>] <location>
- severity: 🔴 | 🟡 | 🟢
- rule: L1 … L7 | R | P
- location: <절 또는 줄>
- quote: <본문 인용>
- message: <무엇이 왜 문제인지>
- recommendation: <고칠 방향. 새 사실을 지어내지 않는다>
```

- 🔴 사실·논증·수치가 틀렸거나 독자를 오해로 이끈다. 🟡 독자가 막히거나 검증이 미완료다. 🟢 참고.
- **범주마다 coverage 행을 남긴다.** 지적이 없는 범주는 `- [Lk] 검토 완료, 이슈 없음 — 확인한 범위: …`로 적는다. 확인하지 못한 범주는 이유와 함께 `미검토`로 적는다.
- 검토 범위(읽은 파일, 연 출처, 열지 못한 출처)를 맨 앞에 적는다.
