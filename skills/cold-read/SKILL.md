# 독자 검토 (cold-reader 부르기)

`nisaba:cold-reader`는 에이전트라서 `/` 목록에 뜨지 않는다. 이 스킬은 사용자가 그 에이전트를 직접 부르는 입구다.

쓴 사람이 놓친 막힘은 대화 맥락을 모르는 독자만 찾는다. 그래서 이 스킬에서 할 일의 대부분은 에이전트에게 넘기지 않을 것을 거르는 일이다.

## 1. 읽힐 글 정하기

- 인자가 파일이면 그 파일을 읽힌다.
- 인자가 폴더면 `page.md`를 찾는다. 본문이 여러 페이지면 독자가 읽는 순서대로 모두 넘긴다. 순서는 스펙이나 목차를 따르고, 없으면 파일 이름 순서를 따른다.
- 인자가 없으면 대화에서 작업 중인 글을 쓴다. 그것도 없으면 사용자에게 묻는다.
- 그림은 본문이 가리키는 이미지 경로를 모은다. 예: `<image source="…">`, `![](…)`, `<img src="…">`. 경로는 본문 파일 위치를 기준으로 풀어 절대 경로로 바꾼다. 없는 파일은 보고에 적는다.

## 2. 독자 요약서 만들기

아래 순서로 찾는다.

1. 인자에 적힌 독자 설명
2. 글 폴더 `spec.md`의 「독자 요약서」 절
3. 둘 다 없으면 사용자에게 한 번에 묻는다. 물을 것은 누구인지, 이미 아는 것, 판단 질문(없어도 된다)이다. 사용자가 배경지식 없는 독자를 원하면 '이미 아는 것'을 비운다.

에이전트에게 넘기지 않는다.

- 판단 질문의 기대 답. 기대 답은 이 대화에만 남겨 두었다가 4단계에서 비교한다.
- 스펙의 나머지(주장 근거 표, 질문 장부, 작성 메모)
- 대화에서 나온 설명, 고치기 전후 표시, 이전 검토 결과

넘길 프롬프트는 이 모양이다.

```
## 독자 요약서
- 누구:
- 이미 아는 것:
- 모르는 것:
- 읽는 목적:
- 판단 질문:
  1. …
## 읽을 파일 (이 순서로)
- <절대 경로>
## 그림
- <절대 경로>
```

## 3. 에이전트 부르기

- `Agent` 도구를 `subagent_type: "nisaba:cold-reader"`로 부른다. 프롬프트에는 2단계의 요약서와 경로 목록만 넣는다.
- 그 에이전트를 쓸 수 없으면 이 플러그인의 `agents/cold-reader.md` 본문(frontmatter 아래)을 general-purpose 서브에이전트 프롬프트 앞에 붙인다.
- 한 회차는 에이전트 한 번이다. 긴 글이면 수만 토큰이 든다. 한 독자가 이어 읽는 페이지 묶음은 한 번에 넘긴다.
- 고친 판을 다시 읽힐 때는 새 에이전트를 부른다. 한 번 읽은 독자는 처음 읽는 독자가 아니다.

## 4. 기록하고 보고하기

글 폴더에 `reviews/state.json`이 있거나 write-explainer 흐름 중이면, 글을 고치기 전에 결과를 기록한다. 스크립트는 이 스킬 폴더 기준 `../write-explainer/scripts/review_state.py`에 있다.

```
python <이 스킬 폴더>/../write-explainer/scripts/review_state.py record --state reviews/state.json --check cold-reader --outcome 통과|미해결 --result "<막힘 수, 판단 질문 결과>" --files <읽힌 글 파일들> <그림 폴더>
```

막힘이 0이고 판단 질문의 답이 모두 기대 답과 맞으면 통과다. 하나라도 어긋나면 미해결이다.

사용자에게는 이렇게 보고한다.

- 읽은 범위: 에이전트가 적은 그대로 옮긴다(읽은 파일, 연 그림, 열지 못한 그림).
- 막힌 곳 표: 위치 · 종류 · 그 자리에 있었어야 할 것
- 판단 질문: 에이전트의 답과 기대 답을 나란히 놓는다. 다르면 '오해'로 표시하고, 그 답을 낳은 본문을 인용한다.
- 독자 한 명의 결과라 회차마다 숫자가 흔들린다는 점을 한 줄 적는다.

이 스킬은 글을 고치지 않는다. 고치는 일은 사용자가 요청하거나 write-explainer 흐름 중일 때 작성자가 한다.
